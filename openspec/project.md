# ContentSpark — SDD Project Context

Generated by `sdd-init`. Source of truth for stack, testing, and current
implementation state used by all subsequent SDD phases (explore, new,
apply, verify).

## Stack

### Backend (`backend/`)
- FastAPI + Uvicorn
- SQLAlchemy 2.0 async ORM + Alembic migrations (2 migrations exist under
  `backend/alembic/versions/`)
- Pydantic (settings via `BaseSettings` in `backend/app/config.py`, request/
  response validation)
- LLM: Groq (Llama 3.1 8B) via LangChain
- Embeddings: Google Gemini (`gemini-embedding-001`, 3072 dims)
- Vector store: Qdrant Cloud (collection `contentspark_knowledge`)
- Agents: LangGraph (`StateGraph` + `TypedDict` state)
- DB: PostgreSQL via Supabase, connection via `postgresql+asyncpg://`
- **All Python commands MUST run via `mamba run -n contentspark ...`.**
  This is a hard project convention, not a suggestion.

### Frontend (`frontend/`)
- Next.js 16 (App Router), React 19, Tailwind CSS 4
- Supabase Auth (`@supabase/supabase-js`, `@supabase/ssr`)
- Chat session store: `frontend/features/chat/store/`
- Markdown rendering: react-markdown + remark-gfm
- Radix UI (Scroll Area)

### Database
- PostgreSQL via Supabase (relational data)
- Qdrant Cloud (vector store for RAG)
